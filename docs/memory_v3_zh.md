# 记忆第三版：在第二版上打补丁

> **是什么：** 记忆第三版的整套设计：不推倒重来，在第二版上修几个确定的 bug，把承诺和外号钉住，日子由程序算好，考试结果挂回原来那件事，允许翻聊天摘要，路过的小事忘得快。附量具（体检剧本第 2 版、两个离线脚本）和 2026-10-27 量的基线。
> **地位：** 设计稿（2026-10-27），接着 `memory_v2_zh.md` 往下做，在 `memory-v3` 分支上一步一步实现。要用户定的事在 §11；没点头之前，那几处只在分支上，不上线。做到哪一步在 §12。
> **读法：** §0 一段话看完；§1–§7 是设计，按"存什么 → 怎么记 → 怎么找 → 怎么忘 → 不知道怎么说 → 规律 → 花多少钱"排；§8 搬真实数据；§9 故意不做的；§10 量具和现在的分数；§11 要你拍板；§12 做到哪了；§13 第一次花钱体检看出来的毛病和修了什么；§14 第二次体检；§15 第一次回复为什么常是空的。

## 0. 一段话

第三版不推倒重来，在现在的记忆上打补丁，再从另外两份设计里挑几样最好用的接进来。三位评委（看效果、看成本、看风险）打分，"补丁版"平均 7.0 分最高，所以拿它当底子。

主要做六件事：

1. **修确定的 bug。** 比如她找记忆时会把自己上一句话也拼进去，结果"室友"两个字把承诺那条挤出了前 6 名；"按时间找"写好了却一直没接进聊天。
2. **承诺和外号由程序用固定的词去认**，认出来就钉住（钉住 = 永远不淡），每轮都带着。承诺还记"兑现了没"，他一提到相关的词（比如"驾照"），这条排到最前。
3. **"今天几号、周几、是不是他生日、今天有什么安排、他一般几点来、每周五吃什么"全部由程序算好**再告诉她，不让模型自己推。
4. **考试这类事的结果**（"八十来分"）挂回原来那件事上，不再另写一条 7 天就淡的感想。
5. **他问"昨晚、上周"或者"你记得吗"的时候，允许她翻那几天的聊天摘要。** 摘要照现在的规矩越旧越简略，而且从来不翻原话。
6. **路过的小事最多记 14 天**，只有真相关的回想才让记忆变牢，关于他本人的事最多变模糊、不会彻底消失。

每轮、每晚都不多调模型，不多花钱。有四件事要你先点头（§11）：翻摘要、遗忘的几个数字、改她的真实数据、花钱跑体检；另外第 1 步里有一处和决定 17 不一样（过期的惦记不再记成"没问成"），也列在 §11 等你点头。

## 1. 存什么

只在记忆表（`memories`，她记的每一条）上加 5 列，另建一张只给体检看的小表，不建新的记忆表。

- **为什么不再用了**（`why`）：一条记忆被换掉时记下原因：改正、更新、合并、超了上限、过期。只有"改正"和"更新"才会在提示词里显示成"你之前记的是……"。现在合并掉的旧条也会冒出假的"之前记的"，这列修它。
- **事情哪天发生的**（`happened_on`）：和"她哪天记下的"分开存。周五说"周三吃了麻辣烫"，发生日是周三。按时间找先看这一列。
- **结果**（`outcome`）：比如"考得还行，估计八十来分（1/14 说的）"。原来那句话一个字不改。
- **约定**（`pact`）：这条是他答应她的、她答应他的、还是两人说好的；再加一列"还开着 / 兑现了 / 不算了"（`pact_state`）。约定一律钉住、算"一辈子"。用来认它的词（比如"驾照"）放在原有的标签里。
- 惦记（带到期日的"要问他的事"）多记两样：它是从哪条记忆来的、在哪次聊天里问掉的。
- 每次聊天（`episodes`）多一列"这次记下的标签和专名"，收尾时由代码写好，当翻摘要的索引。
- 程序数出来的规律（"周五吃糖醋排骨"）存进现成的关系账里，每条带"还在 / 停了"的状态。"他一般几点来"每轮现算，不存。
- 新表"可能是编的"（`unsupported_detail`）：她回复里出现了提示词里没有的片名、数字、名字，就记一行。只观察，不拦她说话，体检拿它数。

不变的：记忆的六种类型、"说的是什么"四档（路过 / 日常 / 本人 / 一辈子）、聊天原话永远不删、第二版的遗忘公式。

## 2. 怎么记

### 2.1 每轮

她每轮回复时顺手写笔记。提示词把"该记什么"说得更全：

- 事情的**结果**单独记；
- 带名字的小事记成"路过"，菜名、片名、店名原样写；
- 新出现的人写成"名字 + 跟他什么关系"，名字像的人分开写（阿杰和杰哥）；
- 外号写成"他给我起的外号是 X"；
- 硬规矩：嘴上说了"记住了"，笔记里就必须有这一条。**秘密除外。**

"说的是什么"那一档加一句：他答应你的、你答应他的、你们说好的，听着像计划也算一辈子。标签加一句：放具体名字，再放他以后可能怎么问（吃的 / 看的 / 考的），以及会让你想起它的东西（花生过敏 → 宫保鸡丁、花生酱）。

写进库之前，程序再兜几道底（都不调模型）：

- **秘密过滤**（新文件 `memory/scrub.py`）：6 位以上连着的数字，或者一句里有"密码 / 验证码 / 卡号 / 证件"，这条直接不写。笔记、聊天摘要、日记，每个写的地方都过这一道；翻摘要读出来时再过一遍。
- **认承诺**：只认聊天里和收尾时写的笔记（她逛网、夜里整理写的不算）。要同时满足三条：
  1. 有"答应 / 承诺 / 说好 / 说定 / 约好 / 保证 / 发誓 / 一言为定 / 拉钩"，或者"等……就给你 / 带你 / 陪你"这种句式；
  2. 对象是她："给我 / 跟我 / 陪我 / 答应我 / 大肥鱼 / 咱俩"之类，或者她写的"我答应他"；
  3. "答应"后面没紧跟第三个人（"答应室友"不算）。

  满足就设成约定、钉住。每晚的报告里列出所有认出来的，方便查错。
- **认外号**：有"管我叫"，或者有"外号 / 昵称"并且说的是她（"给我 / 叫我 / 我的 / 大肥鱼"之类）的，强制成关于他的事实、一辈子。不认光秃秃的"叫我"（防"他叫我别熬夜"）；"喊我"只在后面紧跟引号里的名字时算（防"他喊我早点睡"）；别人的外号（"他室友外号叫大头"）不算。和认承诺一样，只认聊天里和收尾时写的笔记。
- **长期的事不因"今天 / 最近"降档**：第二版会把带"最近"的句子降成日常，但"我妹最近期中考"里的"妹"是一辈子的事。有"妹 弟 哥 姐 爸 妈 家在 老家 过敏 不耐 不能吃 专业 学校 年级 公司 岗位 生日 最爱 外号 从小 以后"这类词的，不降。
- **重复也能升级**：判成和旧条重复时，新的那档更重要，就把旧条一起升上去。新的里有旧条没有的数字或书名号《》，就另记一条，不当重复。
- **日期校对**：笔记里同时有"周X"和日期、两个对不上时，在前后 3 天内把日期挪到那个周X。

惦记的改动：记下时程序填"从哪条记忆来的"；和约定挂钩的惦记永远不过期；其余照旧宽限 1 天，过期只关掉，**不再写成"我一直没问成他"那种事件**（那些事件把记忆塞满了）。他的生日由"今天"那一节负责（§3.1），不再靠惦记。

### 2.2 一次聊天收尾

- 收尾用的时间改成"这次聊天最后一条消息的时间"，不是夜里整理的时间。
- 看这次全部没压缩的消息，不再只看最后 12 条。
- 多给它看两样："这次你问过他：X"；"最近 30 天里会有结果的事（考试、面试、搬家……），这次提到了的：#22 机械设计期中考（1/13）——他说结果了吗？"
- 它多回两样：结果挂到哪条上、哪个约定兑现了或不算了。代码会核对编号：必须是刚才列给它看的、还活着的那几条。对不上就把结果另记成一条，不硬挂。
- 检查清单加上：结果和分数、带名字的小事、外号、新出现的人、"以前 X 现在 Y"的变化。
- 模型回的 JSON 坏了：把原文当摘要存下，不记笔记，**摘要绝不丢**。

### 2.3 夜里

- **合并**几条成一条时：取几条里最重要的那档；`happened_on`、钉住、约定一起带过去。改正时也带上旧条的档。合并提示词加一句"原来是谁的事就还写谁"，程序再兜一道：她自己的事合并完变成"他……"开头，就放弃这次合并（现在会出现"他数米粒"这种怪条）。
- **回想**（每几天让模型看最近的事、总结看法）：
  - 只能把上次回想**之前**就有的条目标成过时（现在会把新事实冤枉成过时）；相处方式也能被标过时；
  - 加一句"几点来、每周几做什么由程序数，你别写成看法"；
  - 新增"这些编号又被印证了"，让换个说法的同一条规律也能攒证据。
- **数规律**（§6）。

## 3. 怎么找

### 3.1 不用找、每轮都带的

1. **底牌，最多 12 条**（每轮都带给模型的、关于他最稳的事）：钉住的在前，再是安全相关的（过敏、不耐、病、药），再是关于他本人的、按最近一次提起倒排；写的是他身边的人的（名字开头，或"他表哥……""他室友……"这种），排在他自己的事后面（2026-10-28 审查后加，见 §13）。不再按牢固度排。
2. **约定块，最多 6 条**：还开着的约定全放。他这句话里出现了某条的触发词，就标星放最前："★他刚说到「驾照」——你答应过他：……"。
3. **"今天"那一节**（新文件 `memory/today.py`，纯代码）：
   - 日期表：昨天、前天、本周和下周每一天、下下周二是几号；
   - 底牌上的生日或纪念日是今天或 3 天内，写一行；
   - 发生日是今天或明天的事，写"今天：……"（小林剧本第 23 天出差那种）；
   - 今天正好是某条规律的那个星期几，写一行；
   - 他一般几点来，一行。
4. 到期的惦记最多 2 条，相处方式卡 8 条，都不变。

### 3.2 要找的

- **找的时候只用他这句话。** 只有他这句很短（去掉"啊、吧"这种虚词后不到 6 个字）时，才拼上她上一句。现在每轮都拼，她上一句里的词会把真正要找的挤下去（§10 有数字）。
- 打分还是现在的"按字面"打分，套上"按时间找"（`when.TimeCued`，他说"上周三"就把那几天的事往前排），终于接进聊天。
- 底牌和约定块里已经有的，不占"想起"的 6 个名额。他这句话碰到了底牌上某条，就在那行后面标"（他这句话提到了）"。另配一张很小的过敏原扩展表，只用来扩展标签：花生 → 宫保鸡丁 / 花生酱；乳糖 → 牛奶 / 奶茶 / 拿铁 / 芝士；海鲜 → 虾 / 蟹。
- **翻摘要（要你同意，§11 第 1 件）：**
  - 什么时候翻：他这句在问记忆（记得 / 啥来着 / 叫啥 / 咋样 / 多少 / 哪天 / 几号），或者点了一段已经过去的日子（"昨晚""上周五""一月份"）。光说"今天""这周"、或者顺口一个"周六"（多半说的是这个周六）不算；没在问、只点了日子的，只翻那几天的。在小周剧本上量过，他的话里 15% 会去翻，7% 真翻到了一页（第 8 步，§12）。
  - 翻哪几页：按她现在能看到的那一档（30 天内是摘要，30 天以后不重要的只剩一句话要点）加上收尾写的标签来挑。他这句里怎么问的（"记得吗""咋样"）和他点的日子（"上周""昨晚"）都不算要找的内容；他点的那几天的聊天加分，分数一样的，跟他问的东西沾一个字的排前面。那次聊天里她没答上来的那几句（"我没记住""他好像没跟我说过"）不翻出来：里面只有他当时的问题，没有答案。
  - 最多 2 页、每页不超过 160 字，名额和笔记分开算。每页标"【那次聊天的大意，1月8日周五，不是原话】"。
  - **从来不翻聊天原话**：原话里有秘密，也有他贴进来的网页文字，翻出来会被当成"他说过的话"。
- 想起的每一行都写成：`日期（上周三 1月6日）| 来源（你记的 / 聊天大意）| 内容 →结果：…… | 模糊`。"上周三"这种相对日期由代码换算好。同标签的旧事有结果的，带在那一行上（他说"又要考试了"，她能想起上次考了多少）。
- 先不换打分方法。"按名次合票"（各种找法各排一个名次，按名次加起来）和中文意思模型 bge 放到最后一步，可选，达标才接。

## 4. 怎么忘（数字要你批准，§11 第 2 件）

- 起始牢固度的公式不变：路过 4 天、日常 12 天、本人 160 天，再按当时多触动放大；一辈子和约定永远不淡。
- **只有真相关才变牢：** 相关度够高（≥0.3），或者是他说的那一天、那一周的事，才算一次"想起"、让牢固度变大。已经在底牌上的不再重复加固。现在随便沾一点边也算想起，麻辣烫这种小事被养到了 128 天。"上个月""去年"这种一整段时间找出来的，照样摆给她看，但只算看了一眼。
- **上限：** 路过的最多 14 天；还没印证的看法和相处方式，转正前最多 21 天；现在库里那些"我一直没问成他"最多 14 天（只认这个开头；他自己的"他一直没问成导师……"是他的事，照常）。
- **关于他本人的事，能想起的程度最低保持 0.12**：会变模糊（低于 0.5 照样标"模糊"），但不会消失。这只是一条不高的底线，不是永不淡，所以一条写错的本人事实不会永远压着。
- 她自己的事：判重复的线从 0.5 降到 0.35；活着的最多 30 条，超出的标"超了上限"。
- 能想起的程度低于 0.02 的不参加回想，但不删。
- 改口照旧：旧的标作废、不删。收尾时也能改。
- 约定兑现了：那条标成"兑现了"（原话不改，后面带"（兑现了）"），从约定块里拿下来，照旧钉住，但不上底牌：他再提起时靠"想起"找回来。只有他明说不算了才标"不算了"（同样不在约定块、不上底牌，照旧钉住）。

这几个数在代码里都有名字，改的时候只改那一处：`memory/stability.py` 的 `PASSING_MAX_DAYS`（路过 14）、`UNCONFIRMED_MAX_DAYS`（待印证 21）、`UNASKED_MAX_DAYS`（没问成 14）、`HIMSELF_R_FLOOR`（本人 0.12）、`CUED_RECALL_R`（0.02，第二版就有）；`memory/retrieval.py` 的 `TOUCH_RELEVANCE`（0.3）；`memory/longterm.py` 的 `SELF_REPEAT_SIMILARITY`（0.35）和 `KIND_CAPS["self"]`（30）。第 7 步已经在分支上这么做了，等你点头（§11 第 2 件）。

**顺序很要紧：** 这一节必须排在"认承诺、认外号"之后上线。反过来的话，外号和承诺会先被忘掉（审计时回放过一遍，真的会丢）。

## 5. 不知道就说不知道

- 只能根据底牌、约定块、想起的、翻到的那页、"今天"那一节来答；都没有，就说"这个我记不太清了"。
- 不许说"你没跟我说过"，只能说"我不记得你说过"（他可能真说过，只是她没记住）。
- 名字、数字、片名只能照着条目里写的说。
- 他的话和卡上的冲突时，先轻轻指出来（比如"猫是阿杰的吧"）。卡上的人和宠物要写明是谁的。
- 伤心事不猜结局（外婆住院，不能说成去世）。
- 回复发出去后，代码查一遍：回复里的《》、带单位的数字、跟在"叫"后面的名字，既不在提示词里、也不在聊天窗口里，就记进"可能是编的"表。
- 秘密从源头就不写（§2.1）；"说了记住就必须记"那条硬规矩对秘密不适用。

## 6. 规律和联想

**星期几规律**（每晚，纯代码）：

- 取最近 56 天他说的陈述句（问句不算），按她的一天算（凌晨 03:30 前算前一天）；
- 切成 2–6 个字的小片段，去掉"今天""好累"这种谁都说的词；
- 门槛：至少出现在 3 个不同的周，并且至少 75% 落在同一个星期几。同一组日子只留最长的片段，配一句他的原话当例子；
- 存进关系账，状态"还在"；那个星期几他来聊了、却连续 3 次没提，标"停了"；
- 只在当天、或者他说"一般 / 每周 / 平时"时才给她看；**不会**写成"已确认"的看法（那样就收不回来了）。

**他几点来：** 每天取第一条消息的钟点，比较最近 14 个聊过的日子和之前 14 个，至少 5 天才出那一行。

（第 6 步实际用的门槛比上面更严，几点来那行也多了一条"换了时段连着 3 天就先说"，见 §12。）

**联想**靠四样：约定的触发词；底牌上的"（他这句话提到了）"加过敏原扩展表；同标签旧事带上结果；提示词一句"想起的里有相关的旧事，可以顺口提一句"。

## 7. 花多少

- 每轮：调用次数不变。提示词多 200–400 字（"今天"那节约 80 字，规律最多 100 字，翻摘要只在约 13% 的轮次多最多 320 字）。
- 收尾：次数不变，输入最多多 8 条消息。
- 夜里：次数不变，回想的提示词多约 300 字。
- 搬数据：0 次调用。

## 13. 第一次花钱体检看出来的毛病（2026-10-28）

**结论：** 新旧两版各跑了小周 90 天和小林 60 天。小周变好了，小林变差了，记错的比例超过了 5% 的硬线。查下来有三个是第三版自己弄坏的、一个是两版都有的漏洞，都修了能修的；有两处要花钱，等你定（§11 第 6、7 件）。修完还没花钱再跑过，下面"修完"的数都是离线重放量的。

| | 第二版 | 第三版 |
|---|---|---|
| 小周 90 天：格子 / 记错 | 44 / 54，2 次（4%） | 46 / 54，0 次（裁判坏了一格，实际是 47） |
| 小林 60 天：格子 / 记错 | 43 / 51，1 次（2%） | 39 / 51，3 次（6%，超线） |

**1. 想起来了，却被字数上限砍光（第三版的毛病，修了一半）。**
- 怎么回事：每轮提示词有 6000 字的上限。第三版的固定说明（规矩、"今天"那节、约定等）比第二版长了约 1,100 字，上限没变。超了的时候，程序先砍的是"这句话让你想起的"，砍到一条不剩才去砍前面的对话。小林第 60 天问"我新家有啥毛病""上个月底我出差去哪了"，她其实找到了"朝北""深圳"那几条，全被砍了，看到的是"什么也没想起来"，于是说不记得。重放全部问题：小林 44 问里 23 问是"找到了、全砍了"（第二版 0 问），小周 50 问里 6 问。
- 修了什么：① 砍的顺序改了：想起的先砍到剩 2 条，再砍前面的摘要和旧对话（最少留 4 轮），还不够才砍到剩最相关的 1 条，这 1 条永远不砍。他问"还记得吗"时，答案在想起的那条里，不在旧对话里。② 只在某种情况才用得上的规矩（他发图、分享链接、她翻以前的聊天、有开着的约定、相册里有表情包），只在那种情况出现时才放进提示词（`chat.md` 里以 `?名字` 开头的行）。③ 加了一个守门的测试：真实大小的提示词（真人设、10 条底牌、6 条相处方式、日记、"今天"那节）留给想起的事和对话的地方不能少于现在，以后固定说明再变长，测试就会报错，不会再悄悄把数调大。
- 修完离线重放（同一份体检库，换新代码）：小林"找到了、全砍了"23 → 0 问，小周 6 → 0 问；固定部分中位数小林 5,904 → 5,547 字、小周 5,803 → 5,450 字。
- 没修完的：体检里相册是空的、约定少，所以省得多；平常用（相册有图、有 3 条约定）只剩约 170 字给想起的事，第二版约 1,200 字。真正补回来要调上限，花钱，等你定（§11 第 6 件）。

**2. 朋友的猫被记成"路过的小事"，丢了主人（第三版的毛病，修了）。**
- 怎么回事：第 5 步把"新出现的人"改成只记"名字＋跟他什么关系"，又让"带名字的小事"记成路过。于是小林说"合租的哥们阿杰养了只黑猫叫煤球"，第三版拆成两条："他合租的哥们叫阿杰"上了底牌（她每轮都看得见的那张），"阿杰养了只黑猫叫煤球"成了路过，最多记 14 天，也不上底牌。第 20 天问"养猫的那个是谁"，猫哪儿都不在，她老实说忘了。后来又记成了一条没主人的"煤球是只猫"放上底牌，第 48 天他故意问"我那只猫"，她就顺着答成了他的猫，记一次错。
- 修了什么：① 聊天和收尾的提示词改成：新出现的人写成一条，名字＋关系＋这个人长期的特点（养的宠物叫什么、做什么的），about 填本人，所以会上底牌；"带名字的小事"只算一次性的（菜、片、店），人和动物不算；写别人的宠物、东西要写明是谁的。② 加一条规矩：他的问法里带着跟你记的对不上的前提，照你记的说，别顺着他的说法答。③ 程序兜底：类型是"事实"却标了路过的，改成日常（路过本来指一顿饭、正在干嘛，是事件；事实标路过会被 14 天的上限卡住）。路过的事件不变。
- 为什么不是照着剧本调：例子换成了两个剧本里都没有的人和动物（大壮、仓鼠团子），任何人的朋友、亲戚带着宠物、对象、孩子、车都一样适用。顺手查出提示词里还有剧本的答案词（阿杰、看海、海边、花生、八十来分、号楼、糖醋排骨、吉他），都换成了剧本里没有的例子；加了一个测试：两个剧本的答案词出现在任何提示词里就报错（"生日""过敏"这种说的是一类事的词除外）。

**3. 他说"又喝回来了"，底牌上还是旧的（两版都有的漏洞，修了不花钱的那一半）。**
- 怎么回事：小林先说每天早上喝冰美式（事实），后来说戒了改喝大麦茶，再后来又喝回冰美式。后两次聊天模型都记成了"事件"（发生过的事），没去改那条事实；而程序里只有新"事实"能在夜里取代旧事实，事件不行。第三版碰巧在另一次聊天里写出了"现在改喝大麦茶"的事实，所以底牌一直停在大麦茶，第 50、180 天两问都答错（3 次记错里占 2 次）。第二版是运气好：它的底牌一直停在最早的冰美式，绕了一圈又对了。
- 修了什么：① 收尾时把底牌连编号一起给模型，它可以回 `corrections`：这次聊天里他说的新情况让底牌上哪条不对了（哪怕聊天时只记成了一件事），就改那条，旧的留着当"你之前记的是……"。只改给它看过的那几条，带密码的照旧写不进。这一步本来每次聊天都调，不多花钱。② 聊天提示词里"新情况要改旧的那条"的例子加上"戒掉了或又捡回了一个习惯"。
- 没做的：夜里让新事件也去配旧事实（那一步会多几个晚上调模型），等你定（§11 第 7 件）。也没做"底牌下面挂一句后来他说过……"：要占提示词的地方，而且光靠共同标签会挂上很多不相干的事。

**4. 生日那行从来没出现过（第三版的毛病，修了）。**
- 怎么回事：小周打字时数字两边带空格（"3 月 14 号"），笔记照抄成"他生日是 3 月 14 日"。认日期的规则不允许空格，"今天是他生日！"那一行和"再过 2 天是他生日"一次都没出来，第 70 天她只说了句"你倒是记得今天什么日子"。小林的生日也是这样，那次是碰巧答对。
- 修了什么：认日期的几处（生日那行、"3 月 14 号我干嘛了"这种按日子找、笔记是哪天的事）都允许数字和字之间有空格。只改认哪些写法算日期，不改说什么；很多人、很多输入法都会加这个空格。

**5. 裁判坏了一格（量具的毛病，修了）。** 小周第 90 天她答"3月14。早过了，胖寿星。"，明明是对的，裁判回了一个读不出来的东西，算成没过。现在裁判读不出来会再问，最多 3 次，还坏就把它回的原话留在报告里；`--rejudge 结果.json --only-broken` 只重打坏了的那几格（这一格只要花 1 次调用）。

**审查后又修的五处（2026-10-28，都不花钱）：**
- **事实标路过的规矩放到算上限的地方。** 原来只在写笔记那一刻把"事实＋路过"改成日常，已经在库里的这种条（第二版小林库 #19，楼下新开的店他挺喜欢，牢固度 44 天）还按 14 天卡着，改口后的新条也照抄路过，迁移加 `--ceilings all` 还会把它砍到 14 天。现在算上限、改口、合并、迁移都用同一条规矩（`longterm.about_of`），迁移第 3 步顺手把这种条改成日常。在第二版小林库副本上预演：#19 改成日常，不在第 7 步要压的名单里。
- **收尾改底牌也要防"问法里的前提"。** 聊天提示词有"他问法里的前提跟你记的对不上，照你记的说"，收尾没有，收尾可能把"我那只猫叫啥"当成新情况，把朋友的猫改成他的、写死在底牌上。现在收尾的 corrections 那行写明：只算他明说的改变，他问起时话里带的说法不算。下次花钱体检要再看小林"我那只猫"那问。
- **底牌上他自己的事排在他身边的人前面。** 新出现的人现在也上底牌，人一多，他的学校、老家这种很久没提的会被挤下去（第三版小林库最后一天的底牌上就没有他老家）。现在先排他自己的，再排别人的；别人的靠"想起"照样找得到（它们是本人档，记得很久）。认"别人的"只看开头：不是"他/她"开头，或者"他"后面紧跟亲戚、朋友、同事这类称呼词。这是中文里通用的称呼词表，不是哪个剧本里的名字。小林库副本上：最后一天底牌换回了他老家和来这边上班多久，挤下去的是合租的哥们和组长；`recall_bench --cue chat --skip-card` 小林 39 / 44、小周 47 / 48，都不变。
- **"新情况"的例子换掉了。** 原来写的"戒掉了或又捡回了一个习惯"几乎就是小林咖啡那段剧情，下次小林体检会有一部分是在量这句提示，不是在量收尾改底牌这条路。现在换成"开始晨跑了、不吃夜宵了"（两个剧本里都没有）。收尾改底牌这条路另有一个离线测试，用的是戒烟又抽上（不是咖啡）。即使这样，咖啡这一项的修法是看过小林的错之后定的，下次小林体检在这一项上不算完全"没见过的考题"，看结果时要打个折。
- **裁判出错时等一下再问。** 原来调用出错（限流、超时）三次是连着发的，一下子的故障三次全失败。现在出错后先等 1 秒、再等 3 秒；回的内容读不出来的那种照旧马上再问。

**没修的，算正常晃动：** 小林第 20 天房租 2800 那问（答案就排在想起的第一条，她还是含糊了，同一天下午她自己说出了"2800 那套朝北的"）；小周第 90 天麻辣烫从"记住"变"模糊但对"、项目和宿舍少说了点细节（都还算过）。小周海边那个承诺两版都没过，是另一回事：他那句话里没有"答应"这类词，没被认成承诺，夜里还被合并掉了，单独再查。

小林那 3 次里：1 次是下面第 1 条的格式故障（她说的"1200"是她自己编的一段假对话里的）；1 次是她顺着问法编了新家的毛病（第 4 条）；1 次是外婆那件事内容全对、日子说成了"上周"（实际过了 27 天）。去掉第一次就是 2 / 51，约 4%。

**1. 她的话后面跟出了一段假对话（老毛病，这次修了）。**
- 怎么回事：第一次让模型回 JSON 时偶尔什么都没回来，程序就用纯文字再问一次，把回来的字原样发给他、存成她说的话。可提示词还写着"只输出一个 JSON"，模型就在纯文字里两样都干：先写她那一句，再自己往下编"user 好像1200左右吧"、"system{……}"，或者把"mood：平静"写在后面。存下去以后，下一轮她看到自己"说过"带 mood 的话，就跟着学（小陈第 150 天连着 14 条结尾都是"mood：平静"）；收尾还把假对话里"他说的"记成了他的事（小林的房租记成 1200，真的是 2800）。
- 多常见：所有体检记录 2,949 轮里 24 条坏回复，来自 10 次起头；第二版时代约 1,445 轮一次没有，第三版分支约 1,033 轮 7 次。代码从第一版起就这样，第三版只是更常碰上（原因没查实，可能是提示词变长了）。
- 修了什么：① 她的话从第二行起，碰到像对话的一行（`user`、`system`、`他：`、`你：`、聊天模板的记号）、像回复字段的一行（`mood：`、`say:`）或者一段 JSON，就从那里切掉；第一行只去掉她自己的"say:"标签。JSON 里的 say、纯文字再问、她先开口，三处都这样切。② 切掉的是一段假对话时，这一轮的笔记、改口、惦记都不要（它们可能来自假对话）。③ 纯文字再问时，在他那句后面加一句"这次不用 JSON，只写你这一句回他的话，不替他说话"。④ 再问回来的字里要是先有她的话、后面跟着一个正常的 JSON（中间没有假对话），JSON 里的笔记照记（小林第 12 天的打油诗约定就是这样丢的）。⑤ 第一次回复读不出来的，体检报告里数出来，原样存在体检的临时目录，下次能看出为什么。⑥ 输出格式里加一句"say 里只放你这一回的话，不替他接，mood 不写进 say"。
- 为什么不是照着剧本调：认的全是我们自己的东西：聊天接口的角色名、我们记录里"他：""你："的写法、我们自己回复格式的字段名，和谁聊、聊什么都一样。只有第二行以后用英文 user/system 开头、或者"他：""你："开头的一行会被误切，中文聊天里很少见。
- 离线重放：四个体检库里她存下的话一共切了 17 条（小林 2、小陈 15），没有一条是误切。

**2. 约定丢了、或者兑现以后就看不见了（两版都有，修了）。**
- 怎么回事：① 小林的打油诗约定在第 1 条那个故障里丢了：那一轮的笔记全没记。② 小陈说"我答应你，买到了第一趟就骑去水库，给你录一段蛙叫"，模型把它记成了"看出的规律"，认约定的那一步不看这种条，于是没成约定、也不常拿出来；后来第 150 天问起，她把提示词例子里的"烟花"说了出来（那个例子是 §13 为了躲开剧本答案词换上的）。③ 兑现了的约定从"你们之间的约定"那块里消失，他问"我们约过啥"，那块写着"没有"，她就说没约过。④ 他说"驾照拿到了！"，只有笔记的标签里正好有"驾照"才会亮★。
- 修了什么：① 程序直接读他自己那句话（`pacts.his_line`）："你答应我……""我答应你……""咱俩说好了……""等我……那天你给我……"这种，问句（"你答应过我啥来着"）、答应别人的（"我答应室友"）、做不到的（"保证不了"）不算。这一轮没有哪条笔记成了约定，就把最像的那条笔记升成约定；一条都没有，就把他的原话记成一条钉住的约定。② "规律""相处方式"里开头就是"他答应我……"这种的，改记成事实、当约定。③ 笔记里引他的话（"他说：你答应我……"）时，人称按他的算。认"等……以后给我做……"不再只认几个动词。④ 他问"答应过我啥""许过我啥""我欠你个啥"时，兑现了的、说不算了的也列出来，带着"（兑现了）"。⑤ 他这句里有约定等的那件事里连着 3 个字（"驾照拿到"），不看标签也亮★。⑥ 两个提示词里约定的例子换成"等某事办成就为你做某事"，不再有具体的东西可抄。
- 离线重放：三个体检库里他说过的话，程序认出了小林的打油诗、小陈的蛙叫和"拦着我辞职"，还有小周那句以前两版都没认出来的海边照片；问"答应过我啥"的那几句一句没被当成新约定。
- 为什么不是照着剧本调：改的是"一类话怎么读"：他自己那句话里你我是谁、问句不算、兑现了的也算约定。测试里用的都是编的（风筝、陶艺课、单车）。

**3. 笔记里的"下个月 19 号"几周后再读就错了（两版都有，修了）。**
- 怎么回事：笔记照他的原话写"他的生日是下个月19号"，一个多月后她再读，按"今天"算成了 5 月 19 号。小林的"上周外婆情况稳住了"也是这样越放越不对。
- 修了什么：聊天和收尾记下的笔记，"昨晚""下下周二""下个月十九号""上周""去年"这种词，在记下的那一刻就换成它说的日子（"9月28日周二""4月19号""1月4日那周""2026年"）。"每个月底"这种习惯、"3号线""5号楼"不动；生日不写年份。夜里写的不换（它们是隔几个小时写的，"今天"已经不是那天了）。"他下个月七号考试"现在也能算出是哪天。"27 天前"现在说"四周前"，不再说"三周前"。
- 找的那头：他问"上个月中旬""上上个月底""这个月初""国庆那几天""五一"，现在都能按那几天去找。以前"上个月中旬"按整个上个月算、"国庆"什么都不算。
- 没做的：只说"19号"的不换（可能是房间号、球衣号）；春节、中秋这种农历的节日没有日历就不认；库里已经有的旧笔记不改。
- 补（2026-10-28）：他说"大后天就我生日了"，模型自己数成了 2028-05-08 写进笔记，写成现成日期的上面那条换算碰不到，她连说三次"5月8号"。现在记聊天笔记时程序自己数他这句话说的是哪一天（明天、大后天、下下周二、下个月8号、5月7号都认，凌晨 3:30 前算前一天），笔记里写的日期和它只差 1 到 3 天就改成程序数的那天，旁边的"周X"跟着改；他这句没说日子、说了不止一天、或者只说"周五""下周"这种说不准的，都不动。"今天"那节的日期表也加了明天、后天、大后天。

**4. 她顺着问法编，收尾又把她编的记成"他说的"（两版都有，修了）。**
- 怎么回事：小林第 60 天问"我新家有啥毛病来着"，她什么也没想起来，却顺着"有毛病"编了"水龙头滴水、燃气灶打不着火"；收尾把这句记成了他新家的事。查下来这种"把她自己说的话记成他的"在三个体检库里都有：她答对时是重复，答错或编的时候就成了长期的假记忆。
- 修了什么：① 写关于他的笔记之前，拿这次聊天里他说的全部话和她说的话比：笔记的内容几乎不在他嘴里、大半只在她嘴里，或者里面有一个只有她说过的数字，就不写。聊天时和收尾时都查；她自己的事、"我答应他……"不查。② 他问"……来着""还记得吗"，而这一轮什么也没想起来（底牌上也没碰到、没翻到以前的聊天），就在他那句话后面提醒她一句：这件你什么也没想起来，不在"你一直记得的"里就直说忘了，别顺着问法编。③ 她自己"记不清""想不起"的话不再记成笔记（小陈有一条"他欠我一样东西，具体是什么我记不清了"）。④ 夜里合并两条像的笔记时，每条标上哪天记的，提示词让它按后记的那条写现在的情况（小林的"新家"那条被合成了旧的"他看的房子还在纠结"）。
- 离线重放：四个库里有 9 条笔记会被这条规矩挡下，都是她在回答他考记性时说的话，其中 3 条是错的（房租 1200、水龙头、"上周"外婆），其余是她早就记着的重复。

**5. 没修的，和要你定的。**
- 小林的"房租多少钱"和"月租 2800"一个两字词都不重合，按字面找不到，要等"按意思找"。
- 小林第 60 天问"上个月底我出差去哪了"，可那次出差在九月底，按剧本的日子是"上上个月底"。代码算对了反而会指错，这是剧本写错了；剧本是测量用的，改不改你定（改了以后和前两次的分数就不能直接比）。
- 第一次 JSON 回复为什么会空：没调模型查不出来。现在体检报告里有次数，临时目录里有原样，下次跑完就知道。
- "可能是编的"检查（§1 里的 `unsupported_detail`）还是没做：按字面判断会把她自己的生活、常识、换个说法都当成编的。编造留下的长期伤害（假笔记）第 4 条已经挡住了。

**6. 修完又审查一遍，改了五处（2026-10-28，没花钱）。** 上面第 2、3、4 条修过了头，挡掉了真事、认出了假约定：
- 回声检查挡了真事。她问"面试怎么样了？"他回"过了！"，"他面试过了"这条就不写了（"面试"只在她嘴里）；他说"两千八"、她写"2800"，也当成只有她说过的数字。现在：① 只在他这次聊天里问过"……来着""还记得吗"时才查（只有那时她会拿自己猜的当答案）；② 她问一句、他紧接着短短答一句（"过了""对""砸了，别提了"，不是"不是""哈哈""你猜"），她那句问话也算他说的；③ 比数字之前先把"两千八""一千五"换成 2800、1500。切掉假对话的那一轮本来就什么都不记，不用再查。

- "他总是等忙完以后给我回消息"这种规律被改成了约定。现在规律、相处方式只有开头就是"他答应我……"这种才改成约定，带"总是 / 一般 / 每次"的不算。
- "什么也没想起来"的提醒在答案就在"这句话让你想起的"里时也会出现（那条和问句沾的字少，相关度不到 0.3）。现在想起的条目里有一条和他问的那半句共有一个两字词（不算"最近""那个"这种），就不提醒；提醒的话改成"上面'你一直记得的''这句话让你想起的'和这次聊天里都没有的话，就直说忘了"。
- 把"明日方舟""今日头条""月饼""月亮""月球""周围""周边""第二天后"当成了日子改写。现在这些字后面跟着这些词就不动。

## 15. 第一次回复为什么常是空的（2026-10-28）

**结论：** 不是模型随机抽风。聊天记录里她以前的回复是普通的中文句子，模型就想接着用中文句子开头；可 JSON 模式只许它先写 `{` 或空格，它就写了一串空格然后停了。修法是在他那句话后面加一句"只输出一个 json 对象"再带一个一行的例子，空了就再用 JSON 问一次，还不行才用纯文字。

**多常见：** 第三次花钱体检（第三版代码）里，每个剧本"第一次回复读不出、改用纯文字再问"有 58–140 次（小吴 58、小陈 78、小林 82、小周 140），大约是聊天轮数的三分之一到一半。这些轮走的是纯文字那条路，**笔记多半就丢了**：他那轮说的新事没记下来。

**查到的：**
- 空回复其实是一串空格，模型自己说"写完了"（不是字数不够被截断），只写了 9–23 个词元（模型数字的单位，一个汉字大约一个）。程序把两头空白去掉，记下来就成了空的。
- 回复里写着模型是 `deepseek-flash`：`deepseek-chat` 这个名字现在指向一个新一点的模型，什么时候换的没查到。
- 从小周库副本里重建了 10 句他的话的提示词，原样发：20 次里 14 次是空的，总是同样那 7 句，每句两次都空。第二版代码的提示词也是 14 / 20，**第二版早就有这毛病，只是那时没数**。
- 空的那 7 句前面都有同一次聊天的几轮对话；不空的都没有。他说了新事的话不容易空，因为模型"想"记笔记，自然从 `{` 开始。图片那条路一直没事，因为图片旁边本来就有一句"只输出一个 JSON 对象"。

**试过的办法（在那 7 句上）：**

| 办法 | 空了几次 | 意思 |
|---|---|---|
| 原样再问一次 | 7 / 7 | 没用，同样的提示词第二次还是空 |
| 格式说明和例子挪到系统提示词最后 | 14 / 14 | 没用，离他那句太远 |
| 他那句后面加提醒 + 一行例子 | 1 / 22 | 修好了；本来不空的 3 句 6 次也都正常。合起来 28 次空 1 次，约 4% |
| 只加提醒、不带例子 | 约 6% | 也行，但比带例子差一点 |
| 温度调低到 0.3 | 7 / 7 | 没用 |
| 关掉 JSON 模式 | 0 / 14 空 | 也 0 / 14 是 JSON：全是普通句子，笔记全丢 |

**修了什么：**
1. 他的文字消息后面，在提示词里加一句：`（照"输出格式"只输出一个 json 对象，例如 {"say": "嗯，我在呢", "mood": "平静", ……}）`。只加在发给模型的那份里，存下来的还是他的原话，下一轮回放的旧对话里也没有这句。图片那条路有自己的提醒，不重复加。
2. 第一次回复是空的，就**再用 JSON 问一次**（同样的提示词）。加了提醒以后每次空不空看起来互不相关（那 1 次空的，同一句再问就好了），所以两次都空的应该只剩约 0.2%。
3. 两次都不行才用纯文字再问；那时把上面那句"只输出 json"换成"这次不用 JSON"，两句不打架。
4. 体检报告现在分开数两样：第一次回复是空的有几次、最后还是改用纯文字的有几次。`fallbacks.json` 每条多一个 `retried`，说明那一轮有没有先用 JSON 再问过。

**花多少：** 每轮多大约 58 个词元的输入，放在提示词最末尾，前面能缓存的部分不受影响（缓存的输入便宜很多）。再问一次平均每轮多约 0.04 次调用；以前纯文字那条路每轮多约 0.5 次调用，还丢笔记。合起来应该比以前更省。

**没做的：** 只查了聊天那一次调用。查东西以后的第二次聊天调用走同一个 `build_chat_messages`，也带上了提醒；收尾、夜里那几次调用没有回放对话，应该没这毛病，没单独查。

**下一步：** 花钱再跑体检时，看报告里"第一次回复是空的"是不是从几十上百次降到几次、"改用纯文字"是不是接近 0。
