# 大肥鱼的记忆怎么设计

> **是什么：** 鱼的整套记忆机制：学人的哪几种记忆、一条记忆长什么样、怎么记下、怎么想起、怎么淡忘、怎么改口、夜里怎么整理；以及对应的代码架构和数据表。
> **地位：** 现行（2026-10-26 用户全批，决定 6）；按 `STATUS.md` §2 的顺序实现，§8 的文件已建到数据层。记忆的模块边界以本文 §8 为准，`architecture_zh.md` §3 只留指针。
> **读法：** 先读 §0–§2（为什么这么设计），写代码前读 §4–§9。数学只在 §5.3 一处。

## 0. 目标：像朋友的记忆是什么样

验收时就看这六条，每条都能用脚本演出来（§10）：

1. **记得你的大事，忘得掉小事。** 你学什么、家在哪、怕什么，一年后还在；你某天中午吃了什么，两周后她想不起。
2. **会惦记。** 你说"周五有机器人演示"，周六她会问"演示怎么样"。
3. **会记混。** 很久没提的小细节，她说"好像是……"；你一提，她"哦对"。
4. **会改口。** 你纠正她，她记新的，但知道"你以前说过另一个"。
5. **会看出规律。** 聊久了她会说"你最近老是半夜才来"。
6. **有自己的日子。** 她的日记前后连得上，昨天"做"的事今天还记得。

还有一个硬约束：**模型一次只能看几千字，而记忆要跨月跨年。** 办法是把"窗口"当工作记忆，只放当下；其余全部放在模型外面（一个 SQLite 文件），每轮只挑一小把塞进去。这和 Yaqi 仓库解决"新会话读不完整个仓库"是同一个办法：

| Yaqi 仓库 | 鱼的记忆 |
|---|---|
| `STATUS.md` 一页，每个会话必读 | "关于你的底牌"：十几条最稳的事实，每轮必带 |
| 账本只追加；推翻要写新条目说明取代哪条 | 记忆条目只追加；改口 = 新条目标记"取代"旧条目，旧的不删 |
| 一轮结束，讨论稿压进 `history/` 只留结论 | 一次聊天结束压成一段摘要，一个月后只留一句话 |
| 术语表：一个代号一行人话 | 条目上的标签，召回时按它找 |
| 钩子每次提交机械地查 | 夜间例行机械地去重、淡化、压缩 |

## 1. 学人的哪些机制

| 人的机制 | 人身上什么样 | 鱼怎么做 | 在哪（§8） |
|---|---|---|---|
| 工作记忆 | 同时只装得下几件事，几十秒 | 最近 20 轮原话 + 一段"这次聊到哪了"的滚动摘要 | `memory/window.py`、`episodes.py` |
| 情景记忆 | 某一次具体的事：什么时候、什么心情 | 每次聊天 = 一个**情景**，结束时写摘要和一句话，打重要度和情绪 | `episodes.py` |
| 语义记忆 | 去掉情境的事实："他学机器人" | 从情景里提炼的"关于你"的条目，反复出现的越来越稳 | `longterm.py`，kind = fact |
| 程序性记忆 | 怎么和这个人相处 | "相处方式"条目：他吃哪套、哪些别提 | kind = howto |
| 自传记忆 | 自己的人生故事 | 她的日记 + 她自己的"生活线"条目（想换鱼缸、数米粒） | `diary.py`，kind = self |
| 前瞻记忆 | 记得之后要做某事 | **惦记**：带到期日的条目，到了就问 | `prospective.py` |
| 情绪标记 | 情绪强的事记得牢 | 情绪强的条目初始稳定度 ×1.5 | `stability.py` |
| 显著性筛选 | 不是什么都记 | 模型给每条 1–10 的重要度；低的淡得快 | importance |
| 睡眠巩固 | 夜里把白天的事归档、提炼 | 夜间例行：收尾情景、去重、查矛盾、反思、写日记、压缩 | `routines/nightly.py` |
| 遗忘曲线 | 不复习就指数衰减；复习一次更耐忘 | 每条有**稳定度 S**；**取回度** R = e^(−t/S)；想起一次 S 变大 | `stability.py` |
| 再认强于回忆 | 自己想不起，别人一提就"哦对" | 自由召回要 R ≥ 0.1；线索很强时 R ≥ 0.02 也能出来，标"被提醒才想起" | `retrieval.py` |
| 回忆即改写 | 想起时会被新信息改掉 | 新事实和旧的矛盾 → 旧的标"被取代"，不删 | `longterm.supersede` |
| 模糊痕迹 | 细节先忘，大意留着 | 情景分级降解：原话 → 摘要 → 一句话 | 夜间压缩 |
| 干扰 | 相似的事混成一团 | 相似条目夜里合并，合并后标"细节不确定" | 夜间合并 |
| 情绪一致性 | 心情影响想起什么 | 召回打分里一点点心情偏置（最后做） | `retrieval.py` |
| 自发回想 | "我突然想起……" | 会话开头小概率提一条老记忆；纪念日必提 | `respond.py` |

不学的：人会"编造"没发生过的记忆（虚构）。她不编：小本本里没有就说不记得。她的"不完美"只是清晰度低（§5.6），不是无中生有。

## 2. 总体：一小一大

```
          ┌────────── 每轮进模型的东西（总共 ≤ 6000 字）──────────┐
          │ 人设（固定，`persona_zh.md`）                 ~1000 字  │
          │ 她的状态：心情一句话 + 今天在干嘛               ~100     │
          │ 关于你的底牌（12 条最稳的事实）                 ~400     │
          │ 这句话勾起的记忆（≤ 6 条，可标"模糊"）           ~400     │
          │ 该惦记的（到期的 ≤ 3 条）                       ~100     │
          │ 这次聊天前面的滚动摘要                           ~300     │
          │ 最近 20 轮原话                                  ~2500    │
          │ 你刚说的                                        ~100     │
          └───────────────────────────────────────────────────┘
                     ▲ 每轮挑                          │ 每轮存
     ┌───────────────┴──────────────────────────────────▼───────────────┐
     │  data/fish.db：messages / episodes / memories / prospective      │
     │                / diary / mood / relationship                      │
     └─────────────────────────────────────────────────────────────────┘
```

聊了一年，进模型的还是这 6000 字。挑的标准是"相关 × 重要 × 新近"（§5.2），底牌保证就算召回漏了，她也不会忘了你是谁。预算超了先砍召回条数，再砍窗口轮数，人设和底牌不砍。

## 3. 记忆的种类（存储层）

| 层 | 表 | 存什么 | 谁写 | 寿命 |
|---|---|---|---|---|
| 原话 | `messages` | 每句话原文 | 窗口 | 永久，只当证据；进提示词的只有最近 20 轮 |
| 情景 | `episodes` | 一次聊天：起止、滚动摘要、收尾摘要、一句话、重要度、情绪 | 情景管理 + 大脑（收尾） | 原话引用 7 天 → 摘要 30 天 → 一句话永久 |
| 长期条目 | `memories` | kind ∈ fact（关于你）/ event（发生过的事）/ howto（相处方式）/ insight（看出的规律）/ self（她的生活线） | 大脑（每轮随手记）+ 夜间（提炼、合并） | 看稳定度 |
| 惦记 | `prospective` | 哪天、因为什么、要问什么 | 大脑 + 夜间 | 问过或过期就关 |
| 日记 | `diary` | 她每天一段 | 夜间 | 永久 |
| 心情 | `mood` | 四个数 | 每轮 | 只有当前值 |
| 关系 | `relationship` | 认识第一天、聊过几天、连续几天、昵称、梗 | 夜间 | 永久 |

## 4. 一条长期记忆长什么样

| 字段 | 是什么 | 例子 |
|---|---|---|
| `id` | 编号 | 41 |
| `kind` | fact / event / howto / insight / self | fact |
| `text` | 一句话，她的口吻，第三人称"他"，带日期不带推测 | 2026-10-26 他说周五有机器人演示，挺紧张 |
| `created` / `source_episode` | 什么时候、哪次聊天记的 | 2026-10-26，情景 7 |
| `importance` | 1–10，模型给（§5.1 的尺子） | 6 |
| `valence` / `arousal` | 情绪：−1 到 1 的好坏，0 到 1 的强弱 | −0.3 / 0.6 |
| `stability` | 稳定度 S，单位天（§5.3） | 86 |
| `last_recalled` / `recall_count` | 上次用到、用过几次 | 2026-10-30 / 2 |
| `superseded_by` | 被哪条取代；空 = 现行 | 空 |
| `merged_from` | 从哪几条合并来的（合并过的细节不可靠） | [12, 19] |
| `tags` | 几个关键词，召回用 | ["演示", "机器人", "课程"] |
| `embedding` | 向量（第二版才有） | — |
| `pinned` | 钉住，永不淡（importance 10 自动钉） | 否 |

## 5. 一条记忆的一生

### 5.1 记下（编码）

两个时机：

- **聊天中随手记。** 每轮模型的回复是一段 JSON：`say`（说的话）、`mood`（她这句的情绪）、`topic`（话题词）、`notes`（值得记的，每条带 kind 和 importance）、`followups`（要惦记的，带日期）、`asked`（这轮问掉了哪条惦记）、`corrections`（哪条旧记忆被改正）。`notes` 直接进 `memories`。不多一次调用。
- **聊天结束（情景收尾）。** 30 分钟没说话、跨了天、或说了再见 → 一次调用：摘要、一句话、重要度、情绪，再补一遍漏记的事实和惦记。

重要度的尺子（写进提示词）：身份、家人、长期状态、关系里的大事 8–10；计划、情绪事件、喜好 5–7；一次性小事 1–4。密码、卡号这类一律不记（人设底线）。

### 5.2 想起（召回）

每轮：

1. 线索 = 你这句 + 她上一句。
2. 候选 = 所有未被取代的条目，先过取回度的门：R ≥ 0.1 可自由想起；相关度 ≥ 0.6 时 R ≥ 0.02 也进，标"被提醒才想起"。
3. 打分：`score = 0.5·相关度 + 0.2·新近度 + 0.3·重要度/10`（Generative Agents 的三项，各归一到 0–1）。相关度第一版用汉字二元组重叠，第二版换本地向量；新近度 = 0.995^(距上次用到的小时数)。
4. 取前 6 条，合计 ≤ 400 字。R < 0.5 的标"模糊"。
5. 被取出的条目：`recall_count` +1，S 按 §5.3 涨，`last_recalled` = 现在。
6. 底牌单独算：`pinned` 或 importance ≥ 8 的 fact，按 S 排前 12 条，每轮都带，不走召回。相处方式卡同理（决定 11）：现行的 howto 按重要度排前 8 条，每轮都带。

### 5.3 淡忘的数学（全文唯一一处公式）

- **取回度** R(t) = exp(−t / S)，t = 距上次用到（没用过就是建立）的天数。R 是"现在能想起的概率"。
- **初始稳定度** S₀ = 2.1^importance 天；情绪强（|valence| ≥ 0.6）再 ×1.5；importance 10 钉住，S = ∞。
- **想起一次**：S ← S × (1 + 1.5 × (1 − R))。快忘了才想起，涨得多（R = 0.1 时 ×2.35）；刚聊过又提，几乎不涨（R = 0.95 时 ×1.08）。这是间隔效应。
- **夜里合并**两条相似的：S = 较大者 × 1.3（反复出现更稳）。
- **门槛**：R < 0.5 模糊；R < 0.1 自己想不起；R < 0.02 提醒也想不起。条目永远在库里，只是没人叫得醒。

按这组数，一条没再提过的事：

| 重要度 | S₀（天） | 几天后开始模糊 | 几天后想不起 |
|---|---|---|---|
| 1 | 2 | 1.5 | 5 |
| 2 | 4 | 3 | 10 |
| 3 | 9 | 6 | 21 |
| 4 | 19 | 13 | 45 |
| 5 | 41 | 28 | 95 |
| 6 | 86 | 59 | 200 |
| 7 | 180 | 125 | 415 |
| 8 | 378 | 260 | 2.4 年 |
| 9 | 794 | 1.5 年 | 5 年 |
| 10 | 钉住 | 不淡 | 不淡 |

一句话：**小事两周忘，中等的事三个月淡，大事一年不动；提过三次的中等事能撑一年。** 这组数是参数不是真理，用户觉得忘得太快或太慢就改 2.1 这个底。

### 5.4 夜里整理（巩固）

触发：box 上的定时器每天 03:30（用户的时区）跑；每次启动她时也先跑一遍，补上错过的夜；`python3 -m fish nightly` 手动跑。**她的一天到 03:30 结束**：凌晨一点的聊天算前一天的。整理的是刚结束的那一天，`routine_runs.nightly` 记着上次整理到哪天，同一天不做两次。认识之前的日子不写日记。八步：

1. 收尾还开着的情景。
2. **去重合并**：新条目和已有条目很像（向量 ≥ 0.9，或字重叠很高）→ 合并成一条，`merged_from` 记下来源。
3. **查矛盾**：同一主题、说法不同的两条 fact → 问模型一次"是更新了还是两件事"→ 更新就把旧的标 `superseded_by`。
4. **反思**（每 7 天，或新情景 ≥ 5 个）：把最近的情景一句话和事实给模型，问三个"我注意到他什么"→ 写成 insight 条目（importance 6–8）。
5. **写日记**：输入 = 今天各情景的一句话 + 心情 + 她的生活线条目；输出 ≤ 80 字，她的口吻。没聊天的日子也写（想他、或她自己的事）。日记里冒出的新生活线（"决定明天开始数米粒"）存成 self 条目，下次才连得上。
6. **压缩**：情景 > 7 天 → 丢掉对原话的引用只留摘要；> 30 天且 importance < 6 → 只留一句话。`messages` 原文永不删。
7. **关系账**：认识天数、聊过几天、连续几天；过期 3 天没机会问的惦记关掉，转成一条 event"我一直没问成他演示怎么样"。
8. 导出 `data/notebook_export.md`，给用户偷看她记了什么（调试用，§11）。

一夜 2–5 次调用。压缩别太狠：一篇 2026 年的论文在长记忆测试上发现"压缩过头"把准确率从 78% 拉到 48%，所以原话引用留一周、摘要留一个月，只对不重要的才压到一句话。

### 5.5 改口（再巩固）

你说"不对，是周四" → 这轮的 JSON 里 `corrections` 指出旧条目的 id 和新说法 → 新条目建立，旧的标 `superseded_by`。底牌和召回只用现行的；但旧条目还在，她可以说"你之前说是周五来着"（召回允许带最多一条"曾经"）。她自己日记里的事不改口，那是她的人生。

### 5.6 故意的不完美从哪来（人设，不是 bug）

| 她的表现 | 来自哪 |
|---|---|
| "好像是……我记不太清了" | 条目 R < 0.5，提示词里标了"模糊" |
| "细节我记混了" | `merged_from` 非空 |
| "我记得有这回事，具体忘了" | 情景只剩一句话 |
| "哦对，你说过！" | 被提醒才想起（R 在 0.02–0.1） |
| 完全不记得 | R < 0.02，或根本没记（importance 低、当时没写进 notes） |

代码永远不伪造记忆；"不完美"只是清晰度低。提示词明写：小本本里没有的就说不记得，不要编。

### 5.7 惦记和突然想起

- **惦记**：`due ≤ 今天` 且没关的 → 进提示词"你想问他的"。她问了（JSON 的 `asked`）→ 关闭。过期 3 天没问成 → 关闭，转成 event。
- **突然想起**：会话第一轮，若超过 1 天没聊：先把昨天的日记给她；再以 15% 概率挑一条 importance ≥ 6、R ≥ 0.5、≥ 14 天没用到的放进"突然想起"。纪念日必放：认识 100 天、去年的今天有过 importance ≥ 7 的事。（10-26 补：纪念日、到期的惦记、太久没聊，都成了她**先开口**的由头，见决定 10；聊天开头的"突然想起"还没做。）

## 6. 每一轮的流程

1. 电话线收到一句话，调 `brain.respond(text, now)`。
2. `episodes.current(now)`：上一情景隔了 > 30 分钟 → 先收尾（一次调用），再开新情景。
3. 心情：读 → 按时钟调。
4. 挑：`recall(线索)` + `prospective.due(now)` + `profile()`（底牌）+ 可能的"突然想起"。
5. `prompt.build(...)`，按 §2 的字数预算裁。
6. `llm.chat`（JSON 模式）→ `parse`：说 / 心情 / 话题 / 记 / 惦记 / 问了 / 改正。解析失败就当纯文本回复，这轮不记。
7. 存：窗口加两句；`notes` → memories；`followups` → prospective；`corrections` → supersede；`asked` → 关惦记。
8. 心情：按她报的情绪、话题是否重复、有没有提吃的，更新四个数，存。
9. 窗口超过 20 轮 → `brain.fold`：最老 10 轮并进情景的滚动摘要（一次小调用）。
10. 把 `say` 回给电话线。

## 7. 什么时候跑、花多少

| 时机 | 做什么 | 调用次数 |
|---|---|---|
| 每轮 | 回复（含随手记） | 1 |
| 每 10 轮 | 折叠窗口 | 1（小） |
| 聊天结束 | 收尾情景 | 1 |
| 每天夜里 | 去重、查矛盾、日记、压缩 | 2–4 |
| 每 7 天 | 反思 | 1 |

一天聊 50 轮 ≈ 55 次调用、约 15 万输入字。按 DeepSeek 2026 年的价格大约几分钱到一毛（前缀缓存命中时更省；人设和底牌是固定前缀，正好能命中）。准确数等接通后看账单，记到 `STATUS.md`。

│   └── schedule.py               due(last_run, now)；launchd 模板在 scripts/

依赖方向，四条：

1. `channels` 只调 `brain.respond`。
2. `brain` 用 `persona`、`memory`、`mood`；`routines` 用 `brain.llm`、`memory`、`mood`。
3. `memory`、`mood` 只用 `storage`。
4. **记忆层不会说话**：`memory/` 里没有任何模型调用，只有数据和数学，所以它能在没有密钥的测试里跑完整条生命周期。

    superseded_by INTEGER, merged_from TEXT, tags TEXT, embedding BLOB,

);
CREATE TABLE prospective (
    id INTEGER PRIMARY KEY, text TEXT, due TEXT, created TEXT,
