# 小屋：她有自己的"物理"生活

> **是什么：** 给她一间湖边小屋和一个小镇的设计草稿：屋里的"现实"由谁改、怎么改，她怎么看见，怎么接上心情和空闲时间。具体的屋子、店、动作、时间规则在 `cottage_rules_zh.md`。
> **地位：** 现行（决定 26，2026-10-28 用户"按推荐做"，§8 五件全按推荐）。代码在 `src/fish/cottage/`，开关 `FISH_COTTAGE` 默认关，改完人设再开。
> **读法：** 先读 §0、§2、§3；要定的在 §8。

## 0. 一句话

**屋子是现实，她的脑子是记忆，两样分开。** 冰箱空了就是空了，她说"我去拿个鸡蛋"变不出鸡蛋。屋子只能被三样东西改：他、规则、时间。她只能看，不能改。

用户 10-27 的原话："这个不是大肥鱼可以自己修改的，这个文件是给她看的，比如说'冰箱空了'，比如说'床没叠好'。"

## 1. 为什么要这个

现在她的生活是"编的，但当真"（人设里的数米粒、想换鱼缸），全在她嘴里说，没有前因后果。最明显的一处：跟她聊吃的，她就不饿了（`mood/state.py` 听到吃的词，饿值直接减 20），等于"聊饱了"。

有了屋子，因果就有了：饿了 → 做饭 → 冰箱空了 → 去菜店。生活感来自"想要，但不能马上有"。慢慢从"只有记忆的陪伴"变成"有自己日子的 AI"。

项目的优先级不变：记忆 > 心情和自己的生活 > 说话像她 > 功能。屋子属于第二档，是给你们的关系加料的，不抢戏。

## 2. 三样东西，分开放

| | 是什么 | 谁能改 | 例子 |
|---|---|---|---|
| 布局 | 屋子长什么样、有什么家具、窗外是什么、镇上有哪些店 | 只有我们，几乎不变 | 一张床、一个小厨房、窗外是湖 |
| 现状 | 此刻屋里是什么样 | 他、规则、时间；**她不能** | 冰箱空了、床没叠、锅没洗 |
| 她的记忆 | 她记得屋里怎么样 | 她自己，会记错 | "冰箱好像还有鸡蛋" |

- 布局写在 `cottage_rules_zh.md`，跟着仓库走。全是编的，不碰隐私，公开没关系。
- 现状存在 `data/` 里（不进 git），一份他直接打开就看得懂、能手改的文件。长什么样见 `cottage_rules_zh.md` §2；格式写代码时再定。
- 记忆还是原来的记忆，不用改。她记错屋里的事，再"看一眼"发现不对，这种小插曲是人设层的不完美，不是 bug。

## 3. 现状怎么变：只有三条路

1. **他改。** 他是房东：给她冰箱塞满菜、送一盆花，手改文件或用一条命令（以后做）。
2. **她做动作，规则算结果。** 她只能选"做饭"这个动作；程序去查冰箱，有菜就扣掉食材、记一条"锅没洗"、饿值下降；没菜就做不成。
3. **时间。** 床每天早上会乱，菜放几天会坏，锅不洗一直在水槽里。睡觉和饭点吃饭也算在这里：身体的事程序替她做，有菜做菜、只有米煮白饭、什么都没有就饿着（写代码时加的：只靠她空闲时自己挑，他聊得多的日子她会一直饿着；决定 26 第 5 条）。纯程序算，不调模型。

一条分工：**规则管"有什么、没什么"，她管"怎么样"。** 饭好不好吃、煮没煮糊，她可以自己说；但她说着说着多出一个鸡蛋，不行。她在聊天里说的话，一律不改现状。

## 4. 她怎么看见

- **聊天时：** 提示词里多一小段"你的小屋"，最多 3 行，只挑跟现在有关的（饿了带冰箱，深夜带床），翻成人话。没带上的，她只能凭记忆。
- **空闲时：** 菜单里多几样屋里的事（做饭、买菜、叠床……），只摆现在做得成的：冰箱空了就不摆做饭，摆买菜。和翻新闻、读书平起平坐，"什么都不干"照旧。还是"你可以，不是你必须"（决定 24）。
- **防抢戏：** 提示词写明"偶尔提一下就好"。模型拿到设定很爱反复用，句句提小屋就腻了。

## 5. 接上现有的东西

| 现有的 | 怎么接 |
|---|---|
| 心情里的"饿"（`mood/state.py`） | 改成真吃了饭才降。聊到吃的不再直接减，最多让她更想吃 |
| 心情里的"精力" | 睡觉、午睡回升；做饭、出门花掉一点 |
| 空闲时间（`brain/leisure/`） | 每个屋里的动作是一个新的"活动"，加一个文件加一行，和读书、刷新闻一样 |
| 夜里整理（`routines/nightly.py`） | 顺手算时间带来的变化：菜坏没坏、床乱了 |
| 日记、她的生活线 | 动作的结果写一行（"去菜店买了青菜"），和空闲时做的事一样进日记 |
| 在追的书（书签） | 读过的书摆上书架 |
| 她住哪（决定 15） | 见 §8 第 1 件 |
| 人设 | "住在他的电脑里"要改成住小屋、用手机跟他聊（§6）。和今晚改鲸鱼娘一起改（`STATUS.md` §3）；人设只有用户能改 |
| 屏幕（以后） | 屏幕上画的就是这间屋子的现状。用户 10-28：做 2D，俯视角像素风（星露谷那一类的画法，不用它的素材）；不做 3D。画面只读现状文件照着画，自己不存任何"现实"：冰箱空了画面里就空，她在做饭小人就站在灶前。素材要能公开（仓库是公开的），她的小人得自己画或找人画 |

## 6. 手机：她和他之间的那条线

用户 10-27："她和我的通信也是通过她的'手机'。"

在她的世界里，**她是住在湖边、用手机跟他发消息的人**，不再是"住在他电脑里"。现在的几样东西都能用手机解释通：

| 现在的 | 在她的世界里 |
|---|---|
| 和他聊天（终端、微信） | 手机上发消息 |
| 发表情包 | 手机相册里存的表情包 |
| 他分享的链接和文件（决定 23） | 手机上点开看 |
| 空闲时翻新闻、刷 B 站 | 躺床上刷手机 |
| 以后接摄像头 | 可以说成"视频通话" |

代码上不用动电话线（`channels/`）：大脑本来就不认识电话线，"手机"只是她世界里的说法，写进人设和小屋布局就行。

**做事花时间，但不耽误回他。** 做饭 40 分钟，去菜店来回半小时，这段时间现状里记着"她在做饭"。他这时发消息，她照常回，只是话里带着："在切菜，等下"。第一版手机一直在身上、不会没电，也不故意晚回。晚回、没电、手机落家里这些是电话线的事，还牵扯微信送达的限制（决定 14），以后再说（§8 第 5 件）。

## 7. 花多少钱

屋里的动作搭在空闲时间已有的那一次调用上（她挑一样、写一句），时间带来的变化纯程序算。基本不多花钱。

## 8. 等用户定的

每件都给了推荐，点头就按推荐来。

1. **小镇在哪。** 决定 15 让她"住"在寝室机所在的真实城市：真实天气、真实的附近店。湖边小屋是编的。推荐：**编一个湖边小镇，但天气、日出日落跟真实城市走。** 理由：营业时间、货架上有什么、离家几分钟，这些规则得我们说了算，真实的超市我们管不了；天气一样，又留住了"我们在同一片天底下"的感觉。决定 15 里的真实店留着，当作"他那边的店"，他提到时她认得。这会改决定 15 第 1 条的意思，定了要加一条新决定。
2. **有没有钱。** 推荐**第一版没有**。限制靠拿得动（一次最多买几样）、放得住（菜会坏、冰箱有大小）、营业时间。钱会牵出"钱从哪来、她要不要上班"一整套，现在太早。
3. **他在聊天里说"送你一盆花"算不算。** 推荐**第一版不算**，现状只认他用命令或手改放进去的东西。不然聊天里一句话（他的或她的）就能改现实，规则就没意义了。缺点是他嘴上送了、屋里却没有，有点出戏；他记得顺手放一下就好。
4. **第一版做多大。** 推荐**小屋加一家菜店**，动作只做睡觉、做饭、买菜、叠床、洗碗，正好把"饿"和"精力"两个数用起来。花店、浇花、打扫、邻居，等第一版跑顺了再加。世界一下铺太大，规则会打架，也看不出她到底有没有因此更像个人。
5. **做事时回消息要不要变慢，手机会不会没电、落在家里。** 推荐**第一版都不会**（§6）。不回消息伤关系，等第一版跑顺了再考虑偶尔"手机在充电，回来才看到"。
